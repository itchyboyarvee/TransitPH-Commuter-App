# TransitPH – 30% Mobile Application Implementation

Build a functional **mobile application prototype called TransitPH**, an integrated multi-modal transit navigation and commuter safety system focused specifically on **CALABARZON, Philippines**.

The goal is to produce approximately **30% implementation of the proposed system**, with a working frontend, backend, database, authentication/access control, navigation, and at least one major functional module.

Do NOT attempt to fully implement every feature in the proposal. Prioritize the core system structure and the most important working functionality.

---

## 1. APPLICATION PURPOSE

TransitPH helps commuters plan trips around CALABARZON by combining:

* Jeepney terminals
* Jeepney routes
* Bus routes
* Walking directions
* Destination information
* Location-specific weather information

The most important feature for this implementation is the **Jeepney Terminal Tracker and Route Finder**.

When a user searches for a destination, the application should be able to show:

1. The nearest/relevant jeepney terminal
2. Routes available from that terminal
3. The destination/areas covered by each route
4. Basic fare information when available
5. Walking instructions to the terminal

The presentation identifies this terminal-and-route functionality as a central part of the proposed solution.

---

# 2. TECHNOLOGY

Build this as a **mobile-first application** that can run through Replit.

Use a practical technology stack that is easy to run and demonstrate in Replit.

Preferred:

* Frontend: React + Vite
* Mobile UI: responsive mobile-first design / PWA
* Backend: Node.js + Express
* Database: SQLite
* ORM/database library: Prisma or another reliable lightweight solution
* Authentication: JWT or session-based authentication
* Maps: use an appropriate map library/API if available
* Weather: use a weather API if an API key is available

If external APIs require credentials that are not available, create a clean service layer and provide realistic mock data so the application remains fully demonstrable.

# 16. ROUTE SEARCH LOGIC

Implement a simple working route-matching algorithm.

The system does NOT need a sophisticated AI routing engine for the 30% implementation.

* destination matches the user's destination
* destination contains the search keyword
* terminal/city is relevant to the starting location

Rank results based on relevance.
